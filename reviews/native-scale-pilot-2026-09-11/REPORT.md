# Native SHIFT: 1,000 tips の段階測定と計算カーネルの改善

採用版は1,000 tipsの10シフト探索で中央値34.4%、既知誤差の固定配置フィットで15.8%短縮した。
16組の最終照合で科学的出力と最適化診断は完全一致した。100シフトの共有探索はなお予算消尽し、
本番bootstrapの計算費用と統計的な採用条件は未検証である。

## 測定対象

基準は `bb70467`。前回の最適化を含むソースを固定し、並行開発中の変更を含めずに測定した。
形質ごとに独立なOU共分散を推定するモデルであり、形質間相関を推定する新モデルの測定ではない。
[事前プロトコル](PROTOCOL.md)と[ソース記録](source.json)を参照。

固定root、alpha-height=1+j、過程tip分散1のOUデータを生成した。シフトは強い末端枝効果で、
共有条件は最大5個の非背景レジームに割り当てる。既知誤差は0.01–0.09、追加誤差推定条件では
さらに分散0.04を生成する。完全観測・固定seedの計算負荷試験であり、一般的な回収率や偽陽性率の評価ではない。

時間は入力生成から処理完了まで（Python起動・importを除く）、メモリはプロセスのピークRSS。
BLAS関連設定は1スレッド、各試験を新規プロセスで順番に実行した。共有ホストを完全に占有した測定ではない。
以下の基準測定は各1回の診断であり、実行時間の上限保証ではない。

探索0.281秒、校正6.133秒、support13.602秒、全体20.021秒、ピーク98.4MiB。
元の探索1回＋校正19回＋support内の2×(1+19)回＝**60回**の探索が全て完了した。
[照合記録](workflow-verification.json)と[生データ](results/workflow.json)を参照。

## 採用した変更と最終反復測定

レジームの伝播を全ノードの親参照からpreorderの部分木区間への代入に変更し、
シフトの検査も指定枝だけを参照する。整数ラベルは元実装と完全一致する。
既知誤差で高頻度に呼ばれるwhiteningの数値回転は、平均レベル幅が32以上の場合に
独立ノードをまとめて計算する。細い木・小さい木は元のスカラー経路を使う。
`math.hypot`と行列式の加算順序は維持し、探索予算・初期値・収束判定を変更しない。

各条件3回、新規プロセス、入力構築を含む秒数の中央値（最小–最大）。
Python 3.10.14、NumPy 1.26.4、SciPy 1.15.2、macOS 26.6.2 x86_64。
最終版のafterは新規に3回測定し、同一ソース・環境・入力・harnessを検証したbeforeを再利用した。
最終比較は完全な交互実行ではなく、同一ホストの経時的負荷差は残る。
各プロセスは独立したfit/searchを行い、プロセス間のウォームアップはない。

## ワークフローと収束予算の追加検証

最終版で32 tipsの校正・supportを再実行し、基準の結果と全60探索の診断が完全一致した。
さらに512 tipsで同じ19校正反復・2 support反復をbefore/afterそれぞれ実施し、
校正統計量・p値・選択配置・support頻度・内部校正・全探索診断が完全一致した。
総時間は79.747→63.643秒（各1回の診断）。512 tipsでも小さな候補プール8を使っており、
1,000 tips・100シフトの本番bootstrap費用へ外挿できない。
既知＋追加誤差推定の100シフトフィットも最終版で再実行し、optimizer診断を含む結果が完全一致した。

100シフト別レジームの同一入力でscreening単体のlasso上限を150から1,000に増やすと、
0.477→0.498秒で全6経路が収束した（各1回）。ただし128候補のうち1枝が入れ替わり、
順位も変わった。これは最終探索の同値性や回収性能を保証しない。
[150反復](screen-150.json)と[1,000反復](screen-1000.json)は診断として保存し、
既定値や今回の探索比較条件は変更していない。

## 再実行

保存した`source.json`・`final-variants.json`には測定時の一時パスとソースhashがある。
一時ディレクトリの永続性には依存せず、基準コミットと`final.patch`から再構築できる。
リポジトリrootから以下を実行する（`/tmp/scale-*`は未使用の出力先に置き換える）。

```sh
mkdir -p /tmp/scale-before /tmp/scale-after /tmp/scale-results
git archive bb70467 | tar -x -C /tmp/scale-before
git archive bb70467 | tar -x -C /tmp/scale-after
git -C /tmp/scale-after apply "$PWD/reviews/native-scale-pilot-2026-09-11/final.patch"
cp reviews/native-scale-pilot-2026-09-11/benchmark.py /tmp/scale-before/tools/benchmark_scale_pilot.py
cp reviews/native-scale-pilot-2026-09-11/benchmark.py /tmp/scale-after/tools/benchmark_scale_pilot.py
python reviews/native-scale-pilot-2026-09-11/compare_final.py /tmp/scale-results /tmp/scale-before /tmp/scale-after
python reviews/native-scale-pilot-2026-09-11/check_equivalence.py /tmp/scale-results
python reviews/native-scale-pilot-2026-09-11/verify_final.py
```

`compare_final.py`は新規before/afterを交互実行する。一般照合は事前の1e-6許容差を使い、
`verify_final.py`は保存した最終結果について費用と出力先だけを除き、optimizerを含め完全一致を再確認する。
単独のworkflow試験は同じharnessへ`--mode workflow --tips 512 --shifts 1 --shared
--pool 8 --refits 8 --screening 200 --output ...`を渡す。`PYTHONPATH`は選択したソースroot、
OPENBLAS/MKL/OMP/VECLIBのスレッド数は全て1に設定する。

保存物の区分: `results/`は初期診断（`*-after`には不採用試作版を含む）、
`comparisons/`はQR比較、`candidate-comparisons/`と`rounded-comparisons/`は
最終cutoff決定前の比較である。採用版の根拠は`final-comparisons/`と`final-followups/`。
プロファイルは`results/*.profile.txt`へ累積時間上位80項目を保存した。
[復元検証](reproduction-verification.json)で基準コミット＋差分が測定ソースと一致することも確認した。

最終版の別レジームK=100探索は481.077秒・304.1MiBで終了し、実際の最大K=100、
再推定256で予算消尽した。全候補・最適化診断・lasso未収束の状態も基準と完全一致した。
この1回の追加測定から安定した高速化率は主張しない。
[16組の厳密照合](final-verification.json)には12反復ペアと、32/512 tipsワークフロー、
追加誤差推定フィット、K=100探索の比較を含む。

既知誤差K=10探索は最終版も600秒で打ち切りとなった
（[終了記録](final-followups/search10-known-after.process.json)）。
before/afterとも完了結果がないため、この条件の探索出力の同値性や速度改善は主張しない。
